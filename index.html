  • 回傳物件資訊與座標 JSON

  • 依查詢條件篩選符合的物件

技術重點與問題解決

如何避免地圖一次載入過多物件？
設定地圖縮放層級門檻，達到指定程度後才執行物件搜尋， 並依目前地圖可視範圍查詢，減少單次載入的物件數量， 避免大量標記影響地圖操作體驗。
如何整合行政區資料與地圖？
使用 GeoJSON 載入縣市及鄉鎮市區界線，搭配 Leaflet 圖層呈現行政區資訊，整合地理區域與地圖找房介面。
地圖範圍如何與搜尋條件連動？
整合搜尋表單與 Leaflet 地圖的 bounds 可視範圍、中心點座標， 透過 AJAX 傳送查詢條件至 MVC 後端。取得結果後，動態產生物件列表與地圖標記， 並依中心點距離排序呈現搜尋結果。

通知流程

STAGE 01產生通知
  1. 取得資料與通知對象 讀取待通知資料、員工綁定資訊及客戶訂閱條件
  2. 判斷通知條件 依訂閱價格、區域、物件類型或議題狀態篩選資料；議題通知僅限上班日發送
  3. 組合訊息 依通知情境準備個別訊息、自動通知或廣告內容、推薦連結
STAGE 02發送
  1. 寫入待發送佇列 將收件對象、訊息分類、主旨及內容寫入通知佇列
  2. 呼叫 LINE API 定時檢查待發送資料，客戶廣告限定 20 點透過 Push API 發送
STAGE 03追蹤
  1. 檢查發送結果 攔截 API 呼叫例外，辨識發送失敗
  2. 更新發送狀態 寫回完成時間， 失敗時加註發送失敗
  3. 保留追蹤紀錄 透過資料庫紀錄協助後續問題排查與維護
第三方服務

技術重點與問題解決

員工如何綁定自己的 LINE 帳號？
員工在官方帳號傳送固定格式的綁定訊息，Webhook 比對人員資料後寫入 LINE ID，之後公司即可直接私訊通知。
如何讓客戶訂閱後收到定期廣告？
透過 LIFF 建立訂閱表單，搭配排程比對訂閱條件，向已開啟訂閱的客戶推送符合條件的物件。
如何管理排程發送與失敗紀錄？
透過定時程序檢查待發送資料，依訊息類型識別收件者並呼叫 LINE Messaging API；客戶廣告限定 20 點發送，避免打擾。 發送後更新完成時間，失敗時加註記錄，方便追蹤與維護。

技術重點與問題解決

如何確保回傳資料可信？
應先依金流規格驗證檢查碼／簽章，並比對訂單編號與金額，再進行狀態更新。
AES 解密時發生 Padding 錯誤
解密過程遇到填充（Padding）相關異常，針對加密設定、 解密方式及填充處理進行排查，確認解密流程與金流規格的一致性。
如何排查金流串接異常？
依序檢查交易參數、加密結果及回傳內容， 逐步定位問題發生的階段，縮小異常排查範圍。

C# 手動移除 PKCS7 Padding 
// AesDecrypt：關閉自動 Padding 驗證
aes.Mode = CipherMode.CBC;
aes.Padding = PaddingMode.None;

// 解密取得原始位元組
byte[] rawBytes = decryptor.TransformFinalBlock(
    cipherBytes, 0, cipherBytes.Length);

// 手動剝 PKCS7 padding，模仿 PHP 的做法：
// 只看最後一個 byte，不做嚴格驗證
int padLength = rawBytes[rawBytes.Length - 1];

// 移除 Padding，還原原始資料
if (padLength > 0 && padLength <= rawBytes.Length)
{
    byte[] outputBytes =
        new byte[rawBytes.Length - padLength];

    Array.Copy(rawBytes, outputBytes, outputBytes.Length);
    return Encoding.UTF8.GetString(outputBytes);
}
// padLength 異常（例如 0 或超過緩衝區長度）
// 保底：不移除 Padding，直接使用原始解密資料
return Encoding.UTF8.GetString(rawBytes);

曾遇到 AES 解密的 Padding 相關異常，因此調整填充處理方式， 改以 PaddingMode.None 解密後手動移除填充。 此為實際處理方式的精簡展示。

專案概述

定時抓取房地產網站的物件資料，格式整理後寫入資料庫， 並搭配排程執行與錯誤處理機制，減少人工蒐集及建檔的重複操作。

資料處理流程

STAGE 01排程啟動
  1. 自動執行 透過 Windows 工作排程器搭配 PS1 / BAT 腳本啟動爬蟲程式
STAGE 02擷取與整理
  1. 載入網站 依網站特性使用瀏覽器自動化工具載入列表頁與物件頁
  2. 解析與清洗 擷取所需欄位、統一資料格式，處理缺漏或異常值
STAGE 03比對與入庫
  1. 比對資料 依物件識別欄位確認是否已存在
  2. 寫入與記錄 新增或更新資料，並處理執行異常

技術重點與問題解決

如何處理網頁載入失敗與爬蟲中斷？
依需求等待指定元素載入，設定逾時時間與重試次數； 遇到例外時記錄錯誤，並依排程或腳本設定處理後續執行。
如何避免重複抓取造成資料重複或未同步更新？
以 UUID 比對資料庫中的既有物件，再依房價、坪數等欄位的異動情況， 判斷新增、更新、完整刷新或略過資料。
